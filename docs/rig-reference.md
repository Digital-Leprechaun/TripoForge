# Reference rigs

The `ue5` and `custom` output profiles use a weighted humanoid `.blend`, `.fbx`, or `.glb`. Projects selecting `rig.spec: "ue5"` use the shared `mixamo2ue5.reference` from installation settings; its built-in fallback is `Converters/Mixamo2UE5/reference.blend`. The 89-bone UE5 Manny Simple reference must be built locally from your own Unreal installation; binary reference assets are excluded from Git and ZIP releases. See [reference setup](../Converters/Mixamo2UE5/README.md). `reference.json` records provenance. The project recipe can live outside TripoForge without copying those assets. `--rig` (or Add rig in the web controller) enables the pass; the UE5 specification internally becomes Mixamo rigging plus UE5 conversion. Explicit/custom `output_rig.reference` paths still resolve relative to their configuration file. A profile name alone does not prove an animation contract.

The current fitter recognizes Epic-style humanoid reference roles and source rigs using those roles or supported Mixamo names. It rejects unsupported correspondence. It fits the reference pose and segment lengths to the source character, transfers reference skin weights using anatomical-region nearest-triangle barycentric interpolation, and exports at most eight influences per vertex. Added finger and twist weights come from the reference. Review deformation for each character.

Conversion preserves the source character's normalized height by uniformly scaling the fitted mesh, skeleton and donor surface together. Local-axis validation compares the shortest rotation angle, treating quaternion signs as equivalent. The offline Blender checks in `scripts/tests/target_rig_rotation.py` cover that comparison; `scripts/tests/target_rig_smoke.py` checks a converted `.blend` against its reference hierarchy and axes, normalized weights and sample limb/finger deformation. Pass `--reference` for a custom reference and `--height-m` to check the requested height.

`scripts/blender/build_reference.py` can construct a weighted Blender reference from an Unreal-exported FBX and a JSON bone transform contract. The input contract contains a `bones` list with names and world-space transforms. The helper reconstructs an implicit armature root, converts centimeters to meters and preserves the transport basis required by the Unreal/glTF roundtrip. Use actual imported bone transforms to verify the result; bone names alone do not prove compatibility.

The Unreal adapter checks names, hierarchy, local bind axes, scales and anatomical child translation directions against the supplied reference mesh. Individual segment lengths may differ unless exact proportions are requested. The animation harness takes your reference project, asset list and animation explicitly.

Blender runs headlessly. Saved `.blend` files support visual review and optional manual refinement; routine generation and binding are scripted. `scripts/blender/apply_unreal_pose.py` applies the animation harness's sampled component-space pose to a saved Blender rig for visual inspection.
